# Typeback — 웹사이트

이 폴더 하나가 통째로 웹사이트입니다. 서버도, 빌드도, 비용도 없습니다.

**공개 주소** : https://dash199446-design.github.io/typeback/

| 파일 | 하는 일 |
|---|---|
| `index.html` | 랜딩 — 설명하는 곳 |
| `restore.html` | 복원 작업실 — 파일을 다루는 곳 |
| `style.css` | 두 페이지 공용 디자인 |
| `landing.js` / `restore.js` | 각 페이지 동작 |
| `endpoint.json` | **접수 가능 여부** — 접수 서버가 켜고 끌 때마다 자동으로 갱신됩니다 |
| `assets/` | 전부 실제 파이프라인 산출물 (스톡·생성 이미지 0장) |

---

## 접수를 켜고 끄기

고객이 파일을 올리려면 복원 서버가 켜져 있어야 합니다.

```
켜기 :  C:\TextRevival\접수시작.bat  더블클릭
끄기 :  그 창을 닫기
```

창을 닫으면 사이트가 **자동으로 「접수 중지」** 로 바뀝니다. 고객이 헛걸음하지 않습니다.

작업 스케줄러에도 등록해 두었습니다 (터미널 세션이 끝나도 살아 있게):

```
schtasks /Run /TN "Typeback 접수"     켜기
schtasks /End /TN "Typeback 접수"     끄기
```

자동 시작은 걸지 않았습니다 — 공개 터널을 여는 일이라 사람이 켜는 것이 맞습니다.

## 사이트를 고쳤을 때

```
python site\stamp.py                     ← 반드시 먼저 (캐시 무효화)
cd C:\TextRevival\site
git add -A && git commit -m "내용" && git push
```

`stamp.py` 를 빼먹으면 **고쳐도 방문자에게는 옛 화면이 보입니다.**
CSS·JS 주소에 내용 해시를 붙여 그 문제를 막습니다.

---

## 이미지를 다시 만들 때

```
python site\make_assets.py     랜딩·검증용 이미지
python site\make_gallery.py    복원 사례 5종 (실제 파이프라인 통과)
```

둘 다 **가상의 샘플을 만들어 실제 복원 시스템에 통과시킨 뒤 촬영**합니다.
고객 파일도, 스톡 이미지도, 생성 이미지도 쓰지 않습니다 — 이유는
`business/11_브랜드.md` §6 에 적어 두었습니다.

## 올리기 전에 반드시 바꿀 것

1. **문의 이메일** — `landing.js` 맨 위 `var 문의이메일 = "";` 한 줄
2. **사업자 정보** — 두 페이지 푸터. 유료로 팔기 전에는 **반드시** 채워야 합니다
   (전자상거래법: 상호·대표자·사업자등록번호·통신판매업 신고번호·주소·연락처)

지금은 무료 베타라 요금을 받지 않습니다. 결제를 붙이는 순간 위 2번은 필수입니다.
