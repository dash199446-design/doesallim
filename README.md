이 폴더 하나가 통째로 웹사이트입니다. 서버도, 빌드도, 비용도 없습니다.
정적 파일이라 GitHub Pages 무료 요금제로 그냥 올라갑니다.

### 왜 «업로드 → 자동 복원»을 아직 안 붙였나

두 가지가 아직 해결되지 않았습니다. 붙여봐야 사고가 납니다.

1. **자동 통과율이 부족합니다.** 실제 파일 실측으로 56줄 중 41줄, 26줄 중 13줄이
   복원됐습니다. 나머지는 «확신 없으니 손대지 않겠다»고 넘긴 것입니다.
   즉 지금은 **거의 모든 건이 사람 확인을 거쳐야** 합니다.
2. **가장 중요한 검사를 서버에서 못 합니다.** 이 프로젝트에서 버그 3건을 잡아낸
   유일한 방법이 «Illustrator 로 열어보기» 였는데, 서버에 Illustrator 를 올리면
   Adobe EULA 위반입니다 (CLAUDE.md 절대규칙 10). 그래서 웹 자동 납품 경로에는
   그 안전망이 없습니다.

그래서 이 사이트는 **«무료 진단 신청»을 이메일로 받는 데까지**만 합니다.
그게 지금 정직하게 약속할 수 있는 범위입니다.

파일 업로드·진단 API·미리보기·결제까지 구현된 코드는 `../web/` 에 이미 있습니다
(로컬에서 동작 확인 완료). 정확도와 법률 항목이 정리되면 그걸 붙이면 됩니다.

## 올리는 법 (한 번만 하면 됩니다)

### 1. GitHub 로그인 (사장님이 직접 — 브라우저가 필요합니다)

```bash
gh auth login
```
`GitHub.com` → `HTTPS` → `Login with a web browser` 를 고르시면 브라우저가 열립니다.

### 2. 올리기

```bash
cd C:\TextRevival\site && gh repo create dwesallim --public --source=. --remote=origin --push
```

### 3. Pages 켜기

```bash
gh api -X POST repos/:owner/dwesallim/pages -f "source[branch]=main" -f "source[path]=/"
```

1~2분 뒤 `https://<깃허브아이디>.github.io/dwesallim/` 에서 열립니다.

### 4. 고쳤을 때 다시 올리기

```bash
cd C:\TextRevival\site && git add -A && git commit -m "update" && git push
```

## 나중에 도메인을 붙이려면

`site/CNAME` 파일에 도메인 한 줄만 넣고 push 하면 됩니다. GitHub Pages 는
무료 요금제에서도 개인 도메인과 HTTPS 를 지원합니다. 도메인 값만 유료입니다(연 1~2만원).
